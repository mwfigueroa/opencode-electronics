# 04 — ADP2230 MCP (instrumentación desde OpenCode)

El Digilent Analog Discovery Pro ADP2230 se controla directamente desde OpenCode mediante herramientas MCP. No requiere scripts manuales: podés generar señales, capturar con el osciloscopio, analizar espectros y más, todo desde lenguaje natural.

## Especificaciones del ADP2230

| Parámetro | Valor |
|---|---|
| **Osciloscopio** | 2 canales, 100 MS/s, 55 MHz BW, 14-bit ADC |
| **Rangos verticales** | ±25 V (1x), ±2.5 V (10x) con sonda atenuadora |
| **AWG** | 2 canales, ±5 V, 50 MS/s, 14-bit DAC, 15 MHz BW |
| **Analizador lógico** | 16 canales DIO, 100 MS/s (máx) |
| **Generador de patrones** | 16 canales DIO, 100 MS/s (máx) |
| **Fuente de alimentación** | 1 salida variable ±5 V (hasta 50 mA por DIO) |
| **Memoria** | Buffer compartido para scope/AWG/logic |
| **Conexión** | USB 2.0 (USB-C) |

### Pinout físico

| Función | Pin/Conector | Color cable |
|---|---|---|
| AWG salida 1 | W1 (BNC) | Amarillo |
| AWG salida 2 | W2 (BNC) | — |
| Scope CH1 | 1+ / 1− (BNC) | Naranja / blanco-naranja |
| Scope CH2 | 2+ / 2− (BNC) | Azul / blanco-azul |
| Trigger externo | T (BNC) | — |
| DIO 0–15 | Header 2×8 | — |
| GND | ↓ (negro) | Negro |

## Herramientas MCP implementadas (8)

Cada herramienta es invocada automáticamente por OpenCode cuando pedís una acción en lenguaje natural. La tabla muestra el mapeo completo de parámetros.

### 1. Información del dispositivo

| Herramienta | `adp2230_info` |
|---|---|
| **Parámetros** | ninguno |
| **Retorna** | `device_name`, `serial`, `connected` |

### 2. Osciloscopio — 1 canal con trigger

| Herramienta | `adp2230_oscilloscope_capture` |
|---|---|
| `channel` | 1 o 2 |
| `sample_rate_hz` | Frecuencia de sampleo (máx ~100 MHz mono, ~50 MHz dual) |
| `buffer_size` | Muestras por captura (potencia de 2 recomendado) |
| `voltage_range_v` | Rango vertical pico a pico (±2.5 V a ±25 V) |
| `offset_v` | Offset vertical en volts |
| `trigger_source` | `"none"`, `"analog"`, `"digital"`, `"external"` |
| `trigger_channel` | Canal de trigger (1 o 2, solo trigger analógico) |
| `trigger_level_v` | Umbral de trigger en volts |
| `trigger_slope` | `"rise"`, `"fall"`, `"either"` |
| `timeout_s` | Timeout máximo de espera |
| **Retorna** | `v_min`, `v_max`, `v_pp`, `v_mean`, `v_rms`, `samples_preview_500`, `time_axis_us_preview_20` |

### 3. Osciloscopio — 2 canales simultáneos

| Herramienta | `adp2230_oscilloscope_dual_capture` |
|---|---|
| `sample_rate_hz` | Frecuencia de sampleo |
| `buffer_size` | Muestras por canal |
| `voltage_range_v` | Rango vertical (ambos canales) |
| `timeout_s` | Timeout |
| **Retorna** | `ch1` y `ch2` cada uno con `v_min`, `v_max`, `v_pp`, `v_mean`, `v_rms`, `samples_preview_200` |

### 4. AWG — Generador de señales

| Herramienta | `adp2230_awg_generate` |
|---|---|
| `channel` | 1 o 2 |
| `waveform` | `"sine"`, `"square"`, `"triangle"`, `"ramp_up"`, `"ramp_down"`, `"noise"`, `"dc"` |
| `frequency_hz` | Frecuencia de salida (0.01 Hz a 15 MHz) |
| `amplitude_vpp` | Amplitud pico a pico (0 a ±5 V) |
| `offset_v` | Offset DC |
| `duty_cycle_pct` | Ciclo de trabajo (0–100%, solo onda cuadrada) |
| `enable` | `true` para encender, `false` para apagar |
| **Retorna** | Configuración actual del AWG |

> **Nota**: La señal persiste en hardware incluso si el proceso MCP termina. Para apagar: `enable: false`.

### 5. Analizador de espectro (FFT)

| Herramienta | `adp2230_spectrum_analyzer` |
|---|---|
| `channel` | 1 o 2 |
| `sample_rate_hz` | Frecuencia de sampleo |
| `buffer_size` | Muestras (potencia de 2 recomendado, 16384 default) |
| `voltage_range_v` | Rango vertical |
| **Retorna** | `peak_frequency_hz`, `peak_magnitude_dBV`, `frequency_resolution_hz`, `frequencies_hz_preview`, `magnitudes_dBV_preview` |

> Usa ventana Hanning y devuelve magnitud en dBV (ref 1 V RMS).

### 6. Analizador lógico

| Herramienta | `adp2230_logic_analyzer_capture` |
|---|---|
| `sample_rate_hz` | Frecuencia de sampleo (máx 100 MS/s, clock base 100 MHz) |
| `buffer_size` | Muestras a capturar |
| `timeout_s` | Timeout |
| **Retorna** | `pin_data_preview`: diccionario `DIO_0` a `DIO_15` con arrays de 0/1 |

> La frecuencia real se ajusta por división entera del clock base (100 MHz).

### 7. Generador de patrones digitales

| Herramienta | `adp2230_pattern_generator` |
|---|---|
| `frequency_hz` | Frecuencia de repetición del patrón |
| `pattern` | Bytes hexadecimales separados por coma: `"0xAA,0x55"` |
| `enable` | Encender/apagar salida |
| **Retorna** | `actual_frequency_hz`, `pattern_bytes`, `pattern_hex` |

> La frecuencia real depende del divider del clock base (100 MHz) y la longitud del patrón.

### 8. Control GPIO individual

| Herramienta | `adp2230_gpio_control` |
|---|---|
| `pin` | Número de DIO (0–15) |
| `direction` | `"input"` o `"output"` |
| `value` | 0 o 1 (solo si direction = output) |
| **Retorna** | `voltage_v`, `output_enabled` |

## Instrumentos WaveForms SDK aún no expuestos en MCP

El SDK de WaveForms (vía pydwf) expone 12 instrumentos en `DwfDevice`. Los siguientes **no están implementados aún** en el servidor MCP pero son accesibles mediante scripts pydwf directos:

| Instrumento pydwf | Descripción | Complejidad |
|---|---|---|
| `analogImpedance` | **Network Analyzer / Bode plot**: barrido en frecuencia con medición de ganancia y fase entre CH1 (referencia) y CH2 (respuesta), usando AWG1 como estímulo | Alta |
| `analogImpedance` | **Impedance Analyzer**: medición de impedancia de componentes (R, L, C) usando resistencia de referencia externa | Alta |
| `protocol.uart` | **Decodificador UART**: transmisión y recepción serie asincrónica | Media |
| `protocol.spi` | **Decodificador SPI**: maestro SPI con captura de MISO/MOSI/SCK/CS | Media |
| `protocol.i2c` | **Decodificador I²C**: maestro I²C con captura de SDA/SCL | Media |
| `protocol.can` | **Decodificador CAN**: transmisión y recepción de tramas CAN | Alta |
| `protocol.swd` | **Decodificador SWD**: depuración ARM Serial Wire Debug | Alta |
| `digitalIO` | **Static I/O digital**: lectura/escritura estática de los 16 pines DIO | Baja |
| `analogIO` | **Voltímetro / fuente DC**: medición de tensión en pines DIO, habilitación de salida de alimentación | Baja |

> **Nota**: La funcionalidad de protocolos (UART/SPI/I²C) se puede implementar en Python post-captura desde los datos crudos del analizador lógico (`adp2230_logic_analyzer_capture`), aunque sin la comodidad del triggering por protocolo que ofrece el SDK nativo.

## Ejemplos de uso

### Ejemplo 1: Generar senoidal 1 kHz / 1 Vpp

> *"generá una señal senoidal de 1 kHz, 1 Vpp en el canal 1 del ADP2230"*

OpenCode invoca `adp2230_awg_generate`:

```json
{
  "channel": 1,
  "waveform": "sine",
  "frequency_hz": 1000,
  "amplitude_vpp": 1,
  "offset_v": 0,
  "enable": true
}
```

**Respuesta:**

```json
{
  "channel": 1,
  "waveform": "sine",
  "frequency_hz": 1000.0,
  "amplitude_vpp": 1.0,
  "offset_v": 0.0,
  "enabled": true
}
```

La señal aparece en **W1** (BNC amarillo). Para apagar:

> *"apagá la señal del ADP2230"*

### Ejemplo 2: Scope con trigger

> *"capturá el canal 1 del scope a 10 MS/s, rango ±5 V, trigger en flanco ascendente a 0.5 V"*

```json
{
  "channel": 1,
  "sample_rate_hz": 10000000,
  "buffer_size": 8192,
  "voltage_range_v": 5.0,
  "trigger_source": "analog",
  "trigger_level_v": 0.5,
  "trigger_slope": "rise"
}
```

Retorna: `v_min`, `v_max`, `v_pp`, `v_mean`, `v_rms` + preview de 500 muestras.

### Ejemplo 3: Scope dual

> *"capturá ambos canales del scope a 1 MS/s, rango ±5 V"*

Invoca `adp2230_oscilloscope_dual_capture` — devuelve `ch1` y `ch2` con estadísticas y preview de 200 muestras cada uno.

### Ejemplo 4: FFT

> *"hacé un FFT del canal 1 a 10 MS/s con 16384 muestras, rango ±5 V"*

Devuelve: `peak_frequency_hz`, `peak_magnitude_dBV`, `frequency_resolution_hz` + espectro completo.

### Ejemplo 5: Analizador lógico

> *"capturá 4096 muestras del logic analyzer a 10 MHz"*

Devuelve estado de los 16 pines (DIO_0 a DIO_15) por cada muestra.

### Ejemplo 6: Patrón digital

> *"generá un patrón 0xAA, 0x55 a 1 kHz"*

Invoca `adp2230_pattern_generator` — devuelve `actual_frequency_hz` (calculada del divider real) y el patrón expandido.

### Ejemplo 7: Loopback AWG → Scope

> *"generá una senoidal de 5 kHz, 2 Vpp en W1 y medila con el scope en CH1"*

OpenCode ejecuta secuencialmente `adp2230_awg_generate` seguido de `adp2230_oscilloscope_capture`, y compara lo generado vs lo medido.

## Requisitos

- ADP2230 conectado por USB
- `pydwf` 1.1.19+ en el entorno Python del MCP
- WaveForms 3.x instalado en Windows (provee `dwf.dll`)
- `usbipd` forwarding activo desde WSL: `adp2230-attach`

## Registro en OpenCode

```jsonc
{
  "mcp": {
    "adp2230": {
      "type": "local",
      "command": ["python", "/ruta/a/mcp-servers/adp2230-server.py"],
      "enabled": true
    }
  }
}
```

## Notas importantes

- **Persistencia del AWG**: la señal sigue activa aunque el proceso MCP termine. Para apagar: `enable: false`.
- **Acceso exclusivo**: un solo proceso puede abrir el ADP2230. Si WaveForms GUI está abierto, cerrá el dispositivo antes de usar el MCP.
- **Pydwf usa enums**: en scripts directos usar `DwfAnalogOutFunction.Sine`, nunca enteros crudos.
- **Divider del clock**: el logic analyzer y pattern generator dividen el clock base de 100 MHz. La frecuencia real puede diferir de la solicitada (el MCP devuelve `actual_frequency_hz`).
- **Rangos del scope**: 500 mVpp a 50 Vpp en pasos discretos. La resolución efectiva depende del rango seleccionado.
