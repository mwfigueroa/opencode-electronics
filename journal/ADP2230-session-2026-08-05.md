## Problemas encontrados y solución final

### ❌ El AWG se apagaba inmediatamente

**Síntoma**: `awg_generate` respondía `"enabled": true`, la señal aparecía un instante en el Tektronix y se apagaba.

**Causa raíz**: Cada tool del MCP usaba `with _get_device() as dev:` → al salir del bloque `with`, se cerraba el device → el AWG se reseteaba.

**Solución**: `_PersistentDevice` — un context manager que envuelve el device y **nunca lo cierra**:

```python
class _PersistentDevice:
    def __init__(self, device):
        self._device = device
    def __enter__(self):
        return self._device
    def __exit__(self, *args):
        pass  # Never close
```

El device se abre una sola vez (singleton con lock) y persiste durante toda la vida del MCP, igual que WaveForms GUI.

## Comportamiento del ADP2230

- **El AWG retiene la última configuración en hardware** incluso si el proceso que lo configuró muere. Para apagar: `awg.configure(0, False)`.
- **Un solo proceso puede abrir el device a la vez**. Si el script AWG está corriendo, el scope falla con `DstmIO failed ERC:3077`.
- **pydwf 1.1.x requiere enums**, no enteros crudos.

## Script AWG directo (respaldo, por si el MCP falla)

```python
from pydwf import DwfLibrary
from pydwf.utilities import openDwfDevice
from pydwf.core.api.analog_out import DwfAnalogOutNode, DwfAnalogOutFunction

dwf = DwfLibrary()
with openDwfDevice(dwf) as device:
    awg = device.analogOut
    c = DwfAnalogOutNode.Carrier
    awg.nodeEnableSet(0, c, True)
    awg.nodeFunctionSet(0, c, DwfAnalogOutFunction.Sine)
    awg.nodeFrequencySet(0, c, 3000.0)
    awg.nodeAmplitudeSet(0, c, 1.0)
    awg.nodeOffsetSet(0, c, 0.0)
    awg.configure(0, True)
    input("AWG activo. Enter para detener...")
    awg.configure(0, False)
```
